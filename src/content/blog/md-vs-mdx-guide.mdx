## 概述

### 什么是 Markdown？

**Markdown** 是一种轻量级标记语言，由 John Gruber 于 2004 年创建。它的设计目标是实现「易读易写」，让人们能够使用纯文本格式编写文档，然后转换成有效的 HTML。

```markdown
# 这是一级标题

这是普通段落，包含 **粗体** 和 *斜体* 文本。

- 列表项 1
- 列表项 2
- 列表项 3

[链接文本](https://example.com)
```

### 什么是 MDX？

**MDX**（Markdown for the component era）是一种基于 Markdown 的格式，允许你在 Markdown 文档中直接使用 JSX 组件。它由 Espresso 团队在 2017 年推出，现已成为内容驱动的 React/Vue/Svelte 应用的标准格式。

```mdx
# 这是一级标题

这是普通段落。

<CustomComponent name="World" />

<Callout type="info">
  这是一个自定义提示框组件！
</Callout>
```

---

## 核心区别

| 特性 | Markdown (.md) | MDX (.mdx) |
|------|---------------|------------|
| **核心定位** | 文档编写格式 | 组件化的内容格式 |
| **语法支持** | 标准 Markdown 语法 | Markdown + JSX |
| **组件支持** | ❌ 不支持 | ✅ 原生支持 |
| **动态内容** | ❌ 静态 | ✅ 支持动态表达式 |
| **前端框架** | 框架无关 | 主要用于 React/Vue/Svelte |
| **编译需求** | 可选（如解析为 HTML） | 必须编译 |
| **学习曲线** | 平缓 | 较陡峭（需了解 JSX）|
| **生态系统** | 极其丰富 | 快速增长 |

## 语法对比

### 1. 基础语法

两者完全兼容：

```markdown
# 标题
## 二级标题

**粗体** 和 *斜体*

- 无序列表
- 列表项

1. 有序列表
2. 列表项

> 引用块

`行内代码`

```代码块```

[链接](url)
![图片](url)
```

### 2. MDX 特有的 JSX 支持

#### 2.1 使用组件

```mdx
import { Chart } from '../components/Chart'
import { Alert } from '../components/Alert'

# 数据分析报告

<Alert type="warning">
  以下数据仅供参考，请以官方发布为准。
</Alert>

<Chart data={salesData} type="line" />
```

#### 2.2 内联 JSX 表达式

```mdx
export const year = 2024

# {year} 年度报告

今年是 {year}，我们取得了 **{growth}%** 的增长！
```

#### 2.3 条件渲染

```mdx
export const isPro = true

{isPro && (
  <ProFeature>
    这是专业版功能
  </ProFeature>
)}
```

#### 2.4 循环渲染

```mdx
export const features = [
  { name: '快速', desc: '极速加载' },
  { name: '安全', desc: '企业级安全' },
  { name: '易用', desc: '简洁界面' }
]

<ul>
  {features.map(feature => (
    <li key={feature.name}>
      <strong>{feature.name}</strong>: {feature.desc}
    </li>
  ))}
</ul>
```

### 3. 属性传递

#### Markdown

```markdown
<!-- 只能通过 HTML 属性 -->
<img src="photo.jpg" alt="描述" width="300" />
```

#### MDX

```mdx
<!-- 可以使用组件的所有功能 -->
<Image
  src="photo.jpg"
  alt="描述"
  width={300}
  height={200}
  placeholder="blur"
  priority={true}
  onLoad={() => console.log('加载完成')}
/>
```

## 组件系统

### 1. 自定义组件映射

MDX 允许你替换原生 Markdown 元素为自定义组件：

```jsx
// components/MarkdownComponents.js
import { CodeBlock } from './CodeBlock'
import { CustomLink } from './CustomLink'

const components = {
  // 替换 h2 标题
  h2: ({ children }) => (
    <h2 className="text-2xl font-bold mt-8 mb-4">
      {children}
    </h2>
  ),

  // 替换代码块
  pre: CodeBlock,

  // 替换链接
  a: CustomLink,

  // 替换图片
  img: ({ src, alt }) => (
    <figure>
      <img src={src} alt={alt} loading="lazy" />
      <figcaption>{alt}</figcaption>
    </figure>
  )
}

// 在 MDX 中使用
<MDXRemote source={mdxSource} components={components} />
```

### 2. 布局组件

```mdx
---
title: 文档标题
---

import { DocsLayout } from '@/components/DocsLayout'

<DocsLayout title={frontmatter.title}>

# 正文内容

这里是文档正文...

</DocsLayout>
```

### 3. 交互式组件示例

```jsx
// React 组件示例
function App() {
  return <h1>Hello React</h1>
}
```

```vue
<!-- Vue 组件示例 -->
<template>
  <h1>Hello Vue</h1>
</template>
```

在 MDX 中可以直接使用交互式组件：

```mdx
<Counter initial={0} />
```

## 使用场景

### 什么时候使用 Markdown？

| 场景 | 原因 |
|------|------|
| **GitHub 文档** | README、CONTRIBUTING 等原生支持 |
| **简单的博客文章** | 纯文本内容，无需交互 |
| **技术文档** | 与 Git 版本控制完美配合 |
| **笔记记录** | 轻量、快速、易迁移 |
| **静态网站生成** | Hugo、Jekyll 等传统 SSG |
| **邮件写作** | 简单、兼容性好 |

**示例：GitHub README.md**
```markdown
# Project Name

> 一句话描述项目

## 安装

```bash
npm install my-package
```

## 使用

```javascript
import { foo } from 'my-package'

foo()
```

## API

详见 [文档](https://example.com/docs)
```

### 什么时候使用 MDX？

| 场景 | 原因 |
|------|------|
| **现代博客** | Next.js、Astro、Gatsby 等框架 |
| **设计系统文档** | 展示可交互的组件 |
| **数据可视化** | 嵌入动态图表 |
| **交互式教程** | 实时代码演示 |
| **营销页面** | 丰富的视觉效果 |
| **文档站点** | Docusaurus、Nextra 等 |

**示例：设计系统文档**
```mdx
import { Button } from '@/components/Button'
import { ButtonShowcase } from '@/components/ButtonShowcase'

# Button 按钮

## 基础用法

<Button>Showcase</Button>

## 变体

<ButtonShowcase />

## API

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| variant | 'solid' \| 'outline' | 'solid' | 按钮样式 |
| size | 'sm' \| 'md' \| 'lg' | 'md' | 按钮尺寸 |
```

```javascript

    rehypePlugins: [require('rehype-prism-plus')],

## 性能考量

### Markdown

| 方面 | 表现 |
|------|------|
| **编译速度** | 极快（纯文本解析）|
| **运行时开销** | 无（预编译为 HTML）|
| **包体积** | 极小 |
| **首屏加载** | 最优 |

### MDX

| 方面 | 表现 | 优化策略 |
|------|------|----------|
| **编译速度** | 较慢（需解析 JSX）| 增量编译、缓存 |
| **运行时开销** | 有（组件 hydration）| 选择性 hydration |
| **包体积** | 较大 | 代码分割、懒加载 |
| **首屏加载** | 可优化 | 静态生成 (SSG)、服务端渲染 (SSR) |

### 优化技巧

```mdx
// 1. 动态导入大型组件
import { lazy, Suspense } from 'react'

const HeavyChart = lazy(() => import('../components/HeavyChart'))

<Suspense fallback={<div>加载中...</div>}>
  <HeavyChart data={data} />
</Suspense>

// 2. 使用 Server Components (Next.js App Router)
// 组件默认在服务端渲染，零客户端 JS
import { ServerComponent } from '../components/ServerComponent'

<ServerComponent />

// 3. 条件渲染
export const showInteractive = false

{showInteractive && <InteractiveComponent />}
```

## 迁移指南

### Markdown → MDX

#### 1. 重命名文件

```bash
# 批量转换
for file in *.md; do
  mv "$file" "${file%.md}.mdx"
done
```

#### 2. 处理 HTML 注释

```markdown
<!-- Markdown 中的 HTML 注释在 MDX 中可能报错 -->

{/* 使用 JSX 注释语法 */}
```

#### 3. 转义特殊字符

```mdx
<!-- 花括号需要转义 -->
\{ 和 \}

<!-- 或使用代码块 -->
`{ config: true }`
```

#### 4. 组件导入

```mdx
---
title: 文章标题
---

import { Image } from 'next/image'
import { Callout } from '@/components/Callout'

<Callout>
  现在可以使用组件了！
</Callout>
```

### 常见问题

| 问题 | 解决方案 |
|------|----------|
| `Unexpected character` | 检查 JSX 语法，确保标签闭合 |
| `Component not defined` | 导入缺失的组件 |
| `Cannot use import statement` | 确保文件扩展名为 `.mdx` |
| `Invalid frontmatter` | 使用 YAML 格式，避免特殊字符 |

## 最佳实践

### 1. 项目结构

```
my-project/
├── content/
│   ├── blog/
│   │   ├── post-1.mdx
│   │   └── post-2.mdx
│   └── docs/
│       ├── intro.mdx
│       └── advanced.mdx
├── components/
│   ├── mdx/
│   │   ├── CodeBlock.tsx
│   │   ├── Callout.tsx
│   │   └── Image.tsx
│   └── ui/
├── lib/
│   └── mdx.ts          # MDX 处理工具
└── next.config.js
```

### 2. 组件设计原则

```tsx
// components/mdx/Callout.tsx
interface CalloutProps {
  type?: 'info' | 'warning' | 'error' | 'success'
  title?: string
  children: React.ReactNode
}

export function Callout({
  type = 'info',
  title,
  children
}: CalloutProps) {
  const styles = {
    info: 'bg-blue-50 border-blue-200 text-blue-800',
    warning: 'bg-yellow-50 border-yellow-200 text-yellow-800',
    error: 'bg-red-50 border-red-200 text-red-800',
    success: 'bg-green-50 border-green-200 text-green-800',
  }

  return (
    <div className={`p-4 rounded-lg border ${styles[type]}`}>
      {title && <strong className="block mb-2">{title}</strong>}
      {children}
    </div>
  )
}
```

### 3. 内容管理

```typescript
// lib/mdx.ts
import { serialize } from 'next-mdx-remote/serialize'
import { readFileSync, readdirSync } from 'fs'
import { join } from 'path'
import matter from 'gray-matter'

const postsDirectory = join(process.cwd(), 'content', 'blog')

export function getPostSlugs() {
  return readdirSync(postsDirectory).filter((file) =>
    /\.mdx?$/.test(file)
  )
}

export async function getPostBySlug(slug: string) {
  const realSlug = slug.replace(/\.mdx?$/, '')
  const fullPath = join(postsDirectory, `${realSlug}.mdx`)
  const fileContents = readFileSync(fullPath, 'utf8')

  const { data, content } = matter(fileContents)
  const mdxSource = await serialize(content)

  return {
    slug: realSlug,
    frontmatter: data,
    content: mdxSource,
  }
}
```

### 4. 类型安全

```typescript
// types/mdx.d.ts
declare module '*.mdx' {
  import type { ComponentType } from 'react'

  const component: ComponentType
  export default component
  export const frontmatter: {
    title: string
    pubDate: string
    description: string
    [key: string]: any
  }
}
```

## 总结

### 选择指南

```
┌─────────────────────────────────────────────────────────────┐
│                     内容格式选择决策树                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  是否需要交互式组件？                                        │
│      ├── 否 → 使用 Markdown                                 │
│      │         • GitHub README                              │
│      │         • 简单文档                                   │
│      │         • 静态内容                                   │
│      │                                                      │
│      └── 是 → 使用 MDX                                      │
│                • 组件展示文档                               │
│                • 数据可视化                                 │

│                • 现代博客                                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 关键要点

1. **Markdown 是内容，MDX 是应用**
   - Markdown 专注于「写什么」
   - MDX 专注于「如何展示」

2. **渐进式采用**
   - 从 Markdown 开始，遇到限制时迁移到 MDX
   - 大多数工具支持同时处理两种格式

3. **团队考虑**
   - Markdown：内容创作者友好
   - MDX：需要前端开发知识

4. **未来趋势**
   - MDX 正在成为内容驱动型应用的标准
   - RSC (React Server Components) 将进一步模糊界限
   - AI 生成内容时代，结构化内容 (MDX) 更有优势
